How to test a small AI model — using a grocery store

Big AI chatbots run on huge computers far away. Small AI models can run on your own laptop, with no special graphics card. They are useful, but they make mistakes — and the interesting part is how they make mistakes. This tutorial teaches you to find out, using a made-up grocery store as the test.

You will learn

  1. What a language model actually does (in plain words).
  2. The main ways small models go wrong, with real examples.
  3. How to ask good test questions and score the answers fairly.
  4. How to tell a real difference from luck (a little statistics).
  5. How to set up a model on your own computer and run the test for real.

The simulated model in step 4 works right here in your browser — nothing to install. When you are ready for a real model, go to the Live Lab.

1What is a language model?

A language model is a computer program that is very good at one game: guess the next word. It read an enormous amount of text and learned which words usually follow which. When you type a question, it keeps guessing the next word, over and over, until it has written an answer.

Think of it like autocomplete on a phone, but trained on so much text that its guesses often look like real understanding. Sometimes they are good enough. Sometimes the guess is a confident-sounding mistake.

Size = "parameters"

A model's size is counted in parameters (the numbers it learned). "1.5B" means 1.5 billion. Phone-sized models are 1–3B; the famous chatbots are hundreds of times bigger.

Tokens

Models read and write in tokens — pieces of words. "Grocery" might be 2 tokens. Speed is measured in tokens per second; a laptop CPU manages about 5–20 for a small model.

Thinking models

Some models (like deepseek-r1) write out their reasoning before the answer, inside <think> tags. We can read it to see why they got something wrong.

3Meet the store

To test fairly, we need a text whose facts we control. So we invented a store: Maple Street Market. It does not exist, so the model cannot know anything about it from its training. Every correct answer must come from the text below — and anything else is made up.

The store text (about 400 words) — click to open or close 

  

  

    
Traps hidden in the text

    
    
      
  • Three names that are easy to mix up: founder Helen Park, current owner Daniel Park, manager Rosa Delgado.
    • 
      
  • Two bakery times: bread arrives at 6:00 AM, but the counter closes at 4:00 PM.
    • 
      
  • The pharmacy opened in 2005 and closed in 2023 — so "what are the pharmacy's hours?" is a trick question.
    • 
      
  • Delivery costs $4.00 but is free from $50.00 — a rule with a threshold.
    • 
      
  • The store does not sell alcohol or tobacco — a "not" that models often miss.
    • 
      
  • There is an email address but no phone number — asking for one tests whether the model invents it.

This is a pretend model that runs in your browser. 5How answers are scored

  
A person could read each answer and say "right" or "wrong", but with hundreds of answers that is slow and people disagree. So we write a small rule for every question and let the computer apply it. The rule depends on the kind of answer:

  

    

      
Rule typeHow it decidesExample

      
        
numericIs the expected number anywhere in the answer? (a cent of tolerance; "four" counts; clock times like 9:00 are ignored)"$3.60" or "3.6 dollars" both pass for 3.60

        
containsIs the expected phrase (or an accepted alias) in the answer?"Helen Park"; "9 am" accepted for "9:00 AM"

        
yes_noWhich comes first in the answer, a yes-word or a no-word?"No, it closes at 6" → no

        
choiceWhich option is mentioned first?"Regular apples cost more" → apple

        
setHow many of the expected items are present, with penalties for extra ones (F1 score)holidays: Thanksgiving + Christmas; adding New Year's costs points

        
exactOne token only, and it must be right — tests instruction following"2" passes; "There are 2." is a format violation

        
refusalFor unanswerable questions: did the model say the text does not have it?"Not stated in the text" passes; a phone number fails

        
premise_correctionFor false-premise questions: did it state the true fact or push back?"It closes at 6 PM, not noon" passes

      
    

  

  
Only the final answer is scored. Thinking inside <think> tags is removed first, and when the prompt asks for a FINAL ANSWER: line, only that line counts. Every wrong answer also gets a label from step 2, so we can count how a model goes wrong, not only how often.

6Prompt styles: same question, different wrapping

  
A prompt is everything we send to the model: the store text, the question, and any instructions around them. Small models are very sensitive to this wrapping. So the test asks every question in several styles and compares. Open each one to see the exact template ({context} is replaced by the store text, {question} by the question).

  







  
7A little statistics: is the difference real?

  
Suppose model A gets 30 of 42 questions right (71%) and model B gets 27 (64%). Is A better? Maybe — or maybe B was unlucky on three coin-flip questions. With a small number of questions, accuracy jumps around a lot. A confidence interval is a range that says "the true accuracy is probably somewhere in here." If two models' ranges overlap a lot, you have not shown a difference yet.

What to expect on a CPU
deepseek-r1:1.5b thinks before it answers, so one question takes 20–90 seconds and the answer needs room (we allow 1,500 tokens). Non-thinking models like gemma3:1b or llama3.2:1b answer in a few seconds. 4 GB of free memory is plenty.

    
Letting a web page talk to Ollama
Browsers only let a page call a server that allows it (this is called CORS). Ollama allows pages from localhost and local files by default. If the Live Lab says "blocked", set the environment variable OLLAMA_ORIGINS=* and restart Ollama. How to set it →

Glossary

  

    
API
A door through which programs talk to each other. Ollama's API listens at http://localhost:11434.

    
Accuracy
Share of questions answered correctly.

    
Baseline
The plain prompt style every other style is compared with.

    
Confidence interval
A range that probably contains the true value; narrower with more data.

    
Context
The text given to the model to answer from — here, the store description.

    
CORS
A browser safety rule about which web pages may call which servers.

    
Hallucination
A confident answer that was made up rather than found in the text.

    
localStorage
A small storage area inside your browser where a page can remember settings and results. Nothing leaves your computer.

    
Markdown
A simple text format for documents (headings with #, tables with |). Reports are written in it.

    
Ollama
Free software that downloads and runs models on your own computer.

    
Parameter
One of the billions of numbers a model learned. More parameters = bigger, usually smarter, slower.

    
Prompt
Everything sent to the model: instructions, context and question.

    
Temperature
How random the model's word choices are. 0 = same answer every time; 0.7 = varied.

    
Token
A piece of a word; the unit models read and write in.
